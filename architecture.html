Key Design Decisions
Filter System
4 global filters, applied to all data

The FilterBar component writes to the useFilters composable's module-level refs — making filter state global without Vuex or Pinia. Every view reads these refs and passes them to API calls. The backend applies them via apply_filters() + filter_by_month() (supports direct month YYYY-MM and quarters Q1-2025).

No Database
In-memory data, no persistence

JSON files in server/data/ are loaded once at startup by mock_data.py into Python lists. All filtering happens in-process. Write operations (create purchase order, tasks) exist but reset on restart — keeping the demo reproducible.

Reactivity Pattern
Raw data in refs, display data in computed

Views store raw API responses in ref() arrays (allOrders, inventoryItems). Computed properties then derive filtered/sorted/aggregated display data. This ensures Vue's dependency tracking works correctly and avoids stale renders.

Ports & CORS
Split-port dev setup

Frontend runs on :3000 (Vite), backend on :8001 (Uvicorn). FastAPI is configured with allow_origins=["*"] for local development. All API calls use the hardcoded base URL http://localhost:8001/api in api.js.
